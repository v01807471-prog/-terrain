# Проверки проекта

## Локальный запуск

Требуется Node.js 22 или совместимая версия.

```bash
npm install
npm run typecheck
npm test
npm run build
```

`npm test` компилирует только необходимые доменные модули в временный каталог `.test-dist/` и запускает их через Node.js. Сторонний test runner и дополнительные runtime-зависимости не требуются.

## Покрытие Terrain

Набор `runTerrainSelfTests()` проверяет:

- детерминизм процедурной CPU-высоты для одинаковых seed/координат и влияние seed на результат;
- детерминизм высоты, вычисленной из Blueprint-графа, и компиляцию всех пяти legacy-пресетов;
- отсутствие предварительной heightmap и ленивое выделение sparse-блоков;
- повторное использование блока, переход через границу блока и отрицательные координаты;
- освобождение блока после обратного мазка;
- разделение процедурной основы и локальной дельты, версии, dirty bounds и отписку от событий;
- транзитивное объединение dirty-прямоугольников, прямую подписку/отписку TerrainUpdateQueue на Terrain, сохранение максимальной версии, приоритет ближайшей области и лимит выдачи;
- выборку обоих треугольников сетки LOD0, нормаль и уклон.

Отдельный набор `runStrokeHistorySelfTests()` проверяет ограничение числа записей, порядок undo/redo, применение старых и новых значений, очистку redo после новой правки и сброс обеих частей истории. Он использует тот же формат записей, что и legacy runtime.

Набор `runStrokeJournalSelfTests()` проверяет отдельный `StrokeJournal`: он запоминает исходное значение индекса только при первом касании за мазок, формирует итоговые массивы `idx/old/nw`, повторно использует буфер меток между мазками и отменяет незавершённую запись без изменения формата истории.

Набор `runBrushMathSelfTests()` проверяет чистые функции `brushMath.ts`: legacy-кривую затухания, ослабление у границ, среднее окно smooth 5×5 (в том числе у края массива) и формулы шести базовых инструментов. Он проверяет математику функций, но не заменяет интеграционные и браузерные проверки полного цикла мазка.

Также запускается существующий набор самопроверок `runTerrainPhysicsSelfTests()` для фиксированного шага, контакта сферы с Terrain и столкновения двух сфер. До выделения журнала мазков было 66 проверок: 48 Terrain/граф/очередь, 6 истории мазков и 12 Physics. Набор `runStrokeJournalSelfTests()` добавляет ещё 13 проверок сбора уникальных индексов, сохранения исходных/итоговых значений, повторных мазков, отмены и проверки границ. `runBrushMathSelfTests()` добавляет ещё 16 проверок формул и граничных условий кистей. Итого до текущего этапа — 95 автоматических проверок.

## Телеметрия React-интерфейса

`src/ui/EditorTelemetry.ts` принимает события `terrain:telemetry` от действующего legacy runtime, проверяет структуру и конечность числовых значений и публикует снимок для React. UI не читает внутренние переменные движка напрямую. При отсутствии события HUD и StatusBar показывают ожидание/прочерк, а не фиктивные координаты, LOD или размер heightfield.

`runEditorTelemetrySelfTests()` проверяет пустое начальное состояние, публикацию валидных данных, уведомления подписчиков, копирование координат, отклонение повреждённых событий, отписку и подключение/отключение адаптера событий. Набор увеличен на 10 проверок: успешный CI на текущем HEAD подтвердил 105 автоматических проверок. Эти проверки подтверждают контракт передачи данных, но не заменяют браузерную проверку расположения панелей и pointer events.

## Что пока не проверяется автоматически

Эти проверки не заменяют браузерные регрессионные сценарии редактора. Они не подтверждают работу реального WebGL-контекста, взаимодействия с панелями, полного sculpt/history workflow, GPU-передачи sparse edits или численное совпадение CPU/GPU на целевых видеокартах. Для этого нужны отдельные browser-тесты и проверка на реальном WebGL-устройстве. Кроме того, успешная сборка подтверждает наличие и компиляцию React entrypoint, но не подтверждает фактическую компоновку `index.html`, работу pointer events, корректность наложения панелей и взаимодействие с legacy canvas в браузере.

## CI

GitHub Actions выполняет в указанном порядке:

1. установку зависимостей;
2. проверку TypeScript;
3. `npm test`;
4. production build через Vite.


## Расчёт размещения основного Clipmap

`runClipmapLayoutSelfTests()` проверяет вынесенный `ClipmapLayout`: прежнюю привязку центров к шагу `2 * step`, отрицательные координаты, высотное переключение LOD, пороги `cut`/`outer`, сохранение последнего уровня, количество видимых тайлов, валидацию входных параметров и повторное использование выходных TypedArray. Проверки подтверждают чистую математику размещения; они не заменяют браузерный тест движения камеры и визуальную проверку переходов geomorph.

Добавлено 12 проверок Clipmap. Общий набор увеличен с 105 до 117 автоматических проверок. Основной Three.js runtime остаётся legacy; браузерная проверка основного Clipmap на реальном WebGL-устройстве ещё не выполнялась.
